# Security Policy

## Supported versions

| Version | Supported |
|---------|-----------|
| 0.x     | ✅        |

Older releases will not receive security fixes.

## Reporting a vulnerability

**Please do not open a public GitHub issue for security problems.**

Use [GitHub private vulnerability reporting](https://github.com/isaacnewton123/viem-error-parser/security/advisories/new) on this repository. Include:

1. A description of the issue and its impact.
2. A minimal proof of concept (code or repository link).
3. Affected versions.
4. Any suggested mitigations.

If GitHub private reporting is unavailable to you, reach out via a direct
message to [@isaac_newton252](https://x.com/isaac_newton252) on X requesting
a secure channel — please **do not** include vulnerability details in the
public message.

## Response timeline

| Step                    | Target          |
|-------------------------|-----------------|
| Initial acknowledgement | within **72 hours** |
| Triage and severity     | within **7 days**   |
| Fix released            | within **30 days** for high-severity issues |

For lower-severity issues we may bundle a fix into the next regular release.

## Disclosure

We follow a coordinated-disclosure model: we will work with you on a public
disclosure date once a fix is available. We credit reporters in the changelog
and security advisory unless you prefer to remain anonymous.

## Scope

This policy covers the `viem-error-parser` library code and its npm distribution.
Vulnerabilities in upstream dependencies (e.g. `viem`) should be reported to
their respective maintainers.
